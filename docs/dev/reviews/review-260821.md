# Whole-project gap review vs current coding & working standards — 2026-08-21

Scope: the committed state of `fnec-rust` audited against our working standards
(code-quality-gates, measurement-integrity, requirements-traceability,
living-docs, change-hygiene, branch-lifecycle, release-checklist,
dependency-audit, coverage-analysis, cross-cutting-seams, pipeline-security).
Two focused sub-audits (traceability; code-level loose ends) plus direct
inspection of CI, hooks, docs, and git state.

**Headline:** the *code* is in good shape — `cargo build --workspace` and
`cargo clippy --workspace --all-targets -D warnings` are green with zero
warnings, test integrity is strong, there is no `unsafe`, and no
input-triggerable library panics. The gaps are almost entirely in **automated
enforcement and traceability**: excellent gate *scripts* and doc discipline
exist, but almost nothing runs them in CI, and several docs claim CI gates that
do not exist.

## Pre-existing breakage found and fixed during the review

10 top-level tracked files (`Cargo.toml`, `Cargo.lock`, `README.md`,
`.gitignore`, `COPYING`, `Makefile`, `SBOM.spdx.json`, `deny.toml`,
`.benchmark-gates.toml`, `.benchmark-hosts.env.example`) were deleted from the
working tree — the workspace could not build. Clean deletions, content intact in
HEAD, no competing changes; restored via `git checkout --`. (Undo with the same
file list if the deletion was intentional.)

## Findings (ranked)

### G1 — No core CI; gates are bypassable hooks only; docs claim CI that doesn't exist — CRITICAL
Standards: code-quality-gates, measurement-integrity, evidence-tiers.
- The only workflow is `.github/workflows/benchmark-dashboard.yml`. There is **no
  CI** running fmt, clippy, test, `cargo audit`, `cargo deny`, coverage,
  frontmatter validation, or the version-bump-docs gate.
- Enforcement is local git hooks only (`.githooks/`), which are bypassable
  (`--no-verify`) and absent for any contributor who hasn't set `core.hooksPath`.
- **Docs assert gates that do not run:** `docs/contributing.md:161` ("The CI
  `validate-doc-frontmatter` job checks every `docs/*.md`"), plus
  `docs/roadmap.md` and `docs/changelog.md:585` ("CI frontmatter gate"). No such
  job exists. This is a measurement-integrity violation — a gate documented as
  running that never runs reads as covered when it is not.
- **Fix:** add a `ci.yml` that runs the scripts the repo already has: `cargo fmt
  --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test
  --workspace`, `cargo audit`, `cargo deny check`,
  `scripts/validate-docs-frontmatter.sh`, and `scripts/check-version-bump-docs.sh`
  on version-touching PRs. Sabotage-verify each job once (break the code, watch it
  fail) per measurement-integrity. Highest leverage single change in this review.

### G2 — Traceability is prose-only: no data source, no in-code binding, no GAP/ORPHAN gate — HIGH
Standard: requirements-traceability. (Full sub-audit confirms all 5 points fail.)
- Requirements live as hand-typed markdown (`docs/requirements.md`,
  `docs/project/requirements-register.md`) — no machine-readable TOML/JSON/YAML
  with lifecycle-status/criticality fields.
- `docs/project/traceability-matrix.md` is a 213-line hand-maintained table (e.g.
  a ~600-word narrative cell appended per PR), not a generated artifact.
- **Zero** `verifies!(ID)` macros and **zero** `// VERIFIES: ID` comments in the
  tree; requirement IDs appear in code only as decorative header comments (294
  `CHK-` mentions). Renaming an ID breaks no build. Matrix↔test links are
  unverifiable prose (e.g. the PH2-CHK-004 cite to `report_contract.rs`, which
  never names the ID).
- No GAP/ORPHAN checker anywhere in scripts/xtask/CI/hooks.
- **Fix (incremental):** (a) add a machine-readable requirements file keyed by ID;
  (b) bind tests with a `// VERIFIES: <ID>` comment + a small checker that fails
  on any requirement with no citation and any citation that didn't run; (c)
  generate the matrix from that data and mark it "DO NOT EDIT". Start with the
  active `PH9`/`GUI-CHK` IDs, backfill the rest.
- **What's already good:** disciplined, coherent ID vocabulary and a genuine
  five-layer human-traceable doc structure — the narrative is strong; only the
  *machine enforcement* is missing.

### G3 — Hook gates weaker than standard — HIGH
Standard: code-quality-gates.
- `.githooks/pre-commit` runs `cargo clippy --workspace --all-targets` **without
  `-D warnings`** — warnings don't block.
- `.githooks/pre-push` runs `cargo test` + `cargo audit` but **not** fmt/clippy
  and **not** `cargo deny check`, so the `deny.toml` license/bans/sources policy
  is never enforced automatically.
- **Fix:** add `-D warnings` to the hook clippy; run `cargo deny check` in
  pre-push (or, preferably, move the whole gate set into CI per G1 and keep hooks
  as a fast local subset).

### G4 — GPU hybrid-dispatch seam is inert (feature silently no-ops) — MEDIUM
Standard: cross-cutting-seams (stub/incomplete-wiring).
- `crates/nec_accel/src/lib.rs:92` `dispatch_frequency_point()` ignores its
  params and always returns `FallbackToCpu`; `DispatchDecision::RunOnGpu`
  (lib.rs:80) is never constructed in production, so the match arms in
  `exec_profile.rs:125,129` and `solve_session.rs:1826` are dead.
- Consequence: `--exec hybrid`'s GPU lane and the startup GPU probe
  (`exec_profile.rs:123-130`, always `gpu_available=false`) are non-functional
  regardless of hardware.
- Mitigation: honestly documented (PH7-CHK-004) and warns the user; the separate
  `--exec gpu` path *is* genuinely wired (`solve_session.rs:1081,1253`,
  `nec_worker/src/solve.rs:220`). So this is incomplete wiring, not a false claim.
- **Fix:** either finish the hybrid dispatch heuristic or, if deferred, add a
  runtime tripwire/test asserting the current documented behavior so it can't
  silently regress, and ensure the roadmap marks it deferred (not done).

### G5 — Living-docs hygiene gaps — MEDIUM
Standard: living-docs.
- `docs/cli-guide.md:8` header still reads **"(v0.2.0)"** while the project is
  v0.12.0 (flagged in a prior review, still open).
- `docs/README.md` index lists ~18 of **65** `docs/*.md` — most docs are not
  indexed.
- `scripts/validate-docs-frontmatter.sh` globs only top-level `docs/*.md`, so
  `docs/project/`, `docs/external/`, `docs/dev/` frontmatter is unvalidated.
- **Fix:** bump the cli-guide header (ideally stamp it from the workspace
  version), complete/auto-generate the index, and extend the validator glob to
  `docs/**/*.md`.

### G6 — Automated dependency/coverage enforcement missing — MEDIUM
Standards: dependency-audit, coverage-analysis, mutation-testing.
- `deny.toml` is complete (licenses/advisories/bans/sources) but `cargo deny
  check` runs nowhere automatically (see G3/G1).
- No committed coverage or mutation config; coverage is a manual `cargo llvm-cov`
  run (per the pre-v0.12.0 review). No coverage floor / no-regression gate.
- SBOM has 527 package entries vs ~554 `[[package]]` in `Cargo.lock` (same commit
  timestamp) — likely legitimate dedup/exclusion, but worth a one-time confirm
  that nothing shipped is omitted.
- **Fix:** add `cargo deny check` + a coverage job with a floor to CI; treat
  mutation testing as an optional periodic run.

### G7 — Branch sprawl — MEDIUM
Standard: branch-lifecycle.
- **69 remote branches**; several local branches already squash-merged but not
  deleted (`docs/*`, `feat/*`). Squash-merge makes `git branch --merged` unreliable
  here, so these accumulate.
- **Fix:** triage via PR/merge state (not ancestry): delete proven-merged, keep
  open-PR branches, log dead ends. Enable host-side delete-on-merge.

### G8 — Release v0.12.0 not finalized (informational) — LOW
- `release/v0.12.0` (870dc0e) is pushed but not merged to `main` (03163d1) and no
  `v0.12.0` tag exists. Consistent with "held for explicit go-ahead"; noted for
  completeness, not a defect.

### G9 — GPU readback panics instead of degrading — LOW
- `crates/nec_accel/src/wgpu_device.rs` (`426/427`, `708/709`, `1034/1035`,
  `1237`, `1653/1654`) `device.poll(...).unwrap()` / `rx.recv().unwrap()` on the
  submit/readback path. Adapter/device *acquisition* degrades gracefully, but a
  driver failure *after* dispatch panics. Only reachable with a misbehaving GPU
  present (not from deck input).
- **Fix:** map these to a `FallbackToCpu`/error return so a mid-run GPU fault
  degrades instead of aborting.

### G10 — CI pipeline hardening — LOW
Standard: pipeline-security.
- `benchmark-dashboard.yml` grants workflow-wide `permissions: contents: write`
  (needed only by the gh-pages deploy job) — scope it per-job (default read).
- Third-party actions are float-pinned (`dtolnay/rust-toolchain@stable`,
  `peaceiris/actions-gh-pages@v4`) — SHA-pin them. (No `${{ github.event.* }}`
  injection into `run:` was found; interpolations use controlled values.)

## Strengths (keep)
- Clean library code: green build + `clippy -D warnings`, no `unsafe`, no
  `#[allow(dead_code)]`, no input-triggerable panics; the few `panic!` hits are
  test-only or documented invariants.
- Strong test integrity: tight real tolerances (Bessel `1e-6`, geometry `1e-12`),
  meaningful negative-path tests, no vacuous/fail-open assertions.
- Disciplined ID vocabulary and a genuine five-layer human-traceable doc set.
- Living-docs machinery (frontmatter validator + `last_updated` stamper) exists
  and works — it just needs to be applied in CI and to nested docs.

## Recommended order of remediation
1. **G1** — stand up core CI from the existing scripts (unblocks G3/G5/G6 too and
   makes the docs' CI claims true). Highest leverage.
2. **G3** — tighten hooks (`-D warnings`, `cargo deny`) as the fast local subset.
3. **G5** — cli-guide version, docs index, validator glob (cheap, high-signal).
4. **G2** — incremental machine-readable traceability + GAP/ORPHAN checker.
5. **G7** — branch cleanup.
6. **G4/G9/G6/G10** — GPU seam decision, graceful GPU fallback, coverage floor,
   CI hardening.
